# Onshape sketch parity tracking

The goal is a comparable sketch authoring workflow, including native geometry, editing tools, constraints, dimensions, and durable dependencies. The existing ring demonstration and native arc demonstration prove specific workflows; they do not prove complete parity.

Reference: [Onshape Sketch Tools](https://cad.onshape.com/help/Content/Sketch/sketch_tools.htm). The original Flowergirl document remains the workflow reference. The table below is the current capability summary. The development sequence below it records incremental evidence and earlier limitations; later entries supersede earlier status statements. Passing tests do not establish coverage of missing tools.

Current implementation entry points: `src/ui/sketch-workspace.ts` owns tool placement and menus; `src/sketch-edit.ts` owns Trim/Split/Extend and relation remapping; `src/sketch-spline.ts` owns periodic interpolation integration, exact portions and anchor provenance; `src/sketch-spline-intersections.ts` supplies native boundary contacts. `src/sketch-value.ts` evaluates arithmetic and units. Driving dimensions now retain their input expression alongside a validated numeric value; typed sketch variables and retained expressions are implemented; references to other dimensions remain absent.

The next feature work must address the remaining authoring capabilities and their dependencies, including native ellipse/elliptic-arc editing, persistent dimensional dependencies, and projected geometry. Numerical spline fixes and passing tests do not substitute for those missing workflows.

Each added operation needs geometry tests, constraint preservation tests, project/PCad round-trip tests where applicable, and integrated-browser proof of the actual workflow. Rendering changes require screenshots under `workdir`. Completion requires examining all remaining areas against the reference, not only the examples already implemented.

Native spline integration: `Spline` is now part of `SketchEntity`, retained as a `sketchSpline` PCad node. Fit splines use uniform natural cubic interpolation; control splines use cubic chains with 3n + 1 points. Point anchors (`point0`, etc.) participate in the solver, snapping, direct dragging, fixed and distance constraints. Translation, rotation, scaling, mirror and patterns preserve native points.

Fit spline and Control spline tools collect points; Finish spline or Enter completes a valid chain. Escape discards incomplete placement. Selected points have coordinate fields, and the canvas draws open curves without an implicit closing chord. Explicit connected edges can close a profile; construction splines contribute no profile. Curve tessellation uses 0.01 mm tolerance for rendering and profiles; crossing selection uses 0.001 mm samples and analytic bounds. Selected control splines display a dashed, non-interactive control polygon that follows point edits. Spline splitting is available through the Split tool; intersections, trimming, offset and curve tangency are not implemented yet.

The geometry helpers retain analytic cubic bounds, exact subdivision, derivatives and adaptive samples with segment/parameter references. ### Compact sketch toolbar

Drawing, editing, constraints, and options now use collapsed menus. Search still finds the tools inside those menus, and Select, undo/redo, fit, finish, and cancel remain directly available. The corresponding Draw, Edit or Constraints menu shows the active tool. Opening another menu closes the previous one; Escape closes a focused menu. Menus overlay the canvas instead of shrinking it.

Escape inside a menu closes it and focuses its summary without cancelling the active drawing tool.
